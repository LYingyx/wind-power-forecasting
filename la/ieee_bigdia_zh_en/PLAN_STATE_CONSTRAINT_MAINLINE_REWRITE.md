# 运行状态约束主线收敛改写方案

## 背景判断

当前实验设计主要回答的问题是：在未来气象已经作为主输入的日内区域风电预测中，预测起点前可用的真实功率状态能否进一步约束气象到功率的映射，并改善预测初期的状态适配。

因此，论文主线应当是：

> 未来气象是日内预测的主驱动；预测起点前的真实功率状态提供运行状态约束；本文设计一种把该约束写入气象读取过程的模型，并通过 Weather-only、Random power、Zero power、Basic GCN 等对比验证约束有效。

“非对称气象-功率融合”可以保留，但应降级为建模动机或结构解释，不能作为第一主贡献。因为当前 benchmark 主要是 Weather-only 和一组不加运行状态约束的气象编码基线，并没有系统比较各种对称/非对称融合策略。如果主线过度强调“非对称融合优于对称融合”，审稿人很容易追问 concat、parallel branch、cross-attention fusion 等融合基线。

## 当前文本的主要风险

### 1. 引言把“非对称融合”抬成了主贡献

位置：

- `sections_short/introduction_zh.tex`

当前问题句：

```tex
本文认为，在业务化日内区域风电预测中，更自然的建模方式是非对称气象-功率融合：未来气象作为主驱动记忆，近期功率作为预测起点处的运行状态约束，作用于未来气象信息的读取过程。
```

风险：

这句话会让读者以为本文主张并验证了“非对称融合”这个范式。但实验没有直接比较不同融合范式，因此这里不宜把“非对称”作为核心论断。

建议改写方向：

```tex
本文关注的重点不是重新比较多源融合范式，而是在未来气象主驱动的日内预测中，显式利用预测起点前可观测的场站功率状态。近期功率记录了当前出力水平、短期惯性和多场站同步变化，可作为运行状态约束参与未来气象信息的读取，从而缓解预测初期的状态失配。
```

这样保留“未来气象主驱动 + 近期功率约束”的逻辑，但不把“非对称融合”放在主语位置。

### 2. 贡献 1 应从“问题表述”改成“约束建模”

位置：

- `sections_short/introduction_zh.tex`

当前贡献：

```tex
\item 从业务时间可用性出发，将区域风电集群预测表述为非对称气象-功率融合问题，明确未来气象的主驱动作用和近期功率的运行状态约束作用。
```

风险：

第一贡献直接使用“非对称气象-功率融合问题”，会让“非对称融合”抢占主线。

建议改为：

```tex
\item 从业务时间可用性出发，分析预测起点前真实功率状态在日内区域风电预测中的作用，将其建模为未来气象驱动预测过程中的运行状态约束。
```

理由：

这条贡献直接对齐实验：Weather-only 已有未来气象，加入真实功率状态后变好，说明运行状态约束有效。

### 3. 方法总览不宜叫“非对称气象-功率融合网络”

位置：

- `sections_short/method_zh.tex`

当前句子：

```tex
如图~\ref{fig:framework} 所示，运行状态约束的非对称气象-功率融合网络由 Weather Encoder、Power-State Encoder 和 Query Decoder 三部分组成。
```

建议改为：

```tex
如图~\ref{fig:framework} 所示，运行状态约束的气象-功率融合网络由 Weather Encoder、Power-State Encoder 和 Query Decoder 三部分组成。
```

理由：

标题已经是“运行状态约束的气象-功率融合网络”。方法名中再加“非对称”会持续强化错误主线。可以在后续解释中说“结构上保留未来气象主驱动、功率状态约束的角色分工”，但不把“非对称”作为方法名。

### 4. 相关工作最后一段有轻微拉踩风险

位置：

- `sections_short/related_work_zh.tex`

当前句子：

```tex
现有特征拼接、并行分支和对称注意力融合通常在特征层面对齐多源输入，难以显式表达这种时间角色差异。
```

风险：

这句话有两层风险：

- 听起来像在否定一类方法，但本文没有和这些方法充分比较。
- “难以显式表达”容易被要求补充对称融合 baseline。

建议改成中性表述：

```tex
已有多源融合研究通常侧重特征互补、空间相关性或时序依赖建模。与这些目标不同，本文关注预测起点真实功率状态在未来气象驱动预测中的约束作用，并将该约束放入气象信息读取过程。
```

理由：

这不是说别人不好，而是说本文关注点不同。这样不会引发“你凭什么说现有方法难以”的审稿风险。

### 5. 气象编码 baseline 不要解释成功率状态替代关系

位置：

- `sections_short/experiments_zh.tex`

当前句子：

```tex
ViT、Swin 和 Video Transformer 在该数据集上未超过 Weather-only，表明单纯提高气象视觉编码器复杂度难以解决预测起点状态失配。
```

风险：

这句话的问题不只是语气偏强，还会把 CNN、3D CNN、ViT、Swin、Video Transformer 这些 baseline 解释为“是否能替代功率状态”。但这些模型并不是为检验功率状态设计的，它们只说明在本文数据和训练设置下，不同气象编码器的纯气象预测表现。运行状态约束的核心证据应来自 Ours vs Weather-only，以及 Random power / Zero power / Basic GCN 等消融。

建议把该段改成中性结果陈述，并把主比较直接落到 Weather-only：

```tex
除 Weather-only 外，3D CNN 是误差最低的气象编码基线，其性能仍低于本文方法。Weather-only 在所有纯气象基线中表现最好，说明该模型已提供较强的气象驱动参照。在相同气象输入和解码器设置下，本文方法相对 Weather-only 将整体 MAE 降低约 4.1\%、RMSE 降低约 2.9\%，说明预测起点前真实功率状态提供了有效的运行状态约束。
```

理由：

这样不对气象编码器做泛化评价，也不把它们解释成“替代功率状态”的实验。纯气象基线只用于交代 Weather-only 的参照强度；机制归因只落在相同气象输入和解码器下的 Ours vs Weather-only。

### 6. 表述“完整未来气象已经提供主要预测信号”可以保留

位置：

- `sections_short/experiments_zh.tex`
- `sections_short/conclusion_zh.tex`

这类表述是安全的，因为它来自实验结果，并且与本文主线一致：

```tex
Weather-only 是所有基线中最强的模型，表明完整未来气象预报已经提供了主要预测信号。
```

但建议后面紧接“本文提升来自真实功率状态约束”，不要展开成“非对称融合更合理”。

## 建议的新主线结构

### 摘要

摘要当前方向基本正确，已经以“运行状态约束”为主，不需要大改。可以微调最后一句，让结论更贴实验：

当前：

```tex
结果说明，预测起点前的真实功率状态能够有效约束气象到功率的映射，提高区域风电集群预测的状态适应能力。
```

可保留。

### 引言

建议引言四段分别承担：

1. 区域风电集群日内预测的重要性和状态失配问题。
2. 未来气象是主驱动，但预测起点功率状态影响映射。
3. 本文不主张“某种融合范式优于其它范式”，而是把真实功率状态作为运行状态约束注入气象驱动预测。
4. 方法概述和贡献。

贡献建议改为：

```tex
\item 从业务时间可用性出发，分析预测起点前真实功率状态在日内区域风电预测中的作用，将其建模为未来气象驱动预测过程中的运行状态约束。
\item 提出运行状态约束的气象-功率融合网络，在 memory 层面注入动态功率上下文 token，使气象读取过程受到预测起点运行状态的约束。
\item 在吉林区域 58 个风电场站数据上验证方法有效性。结果表明，在相同气象输入下，引入真实功率状态约束可稳定降低整体误差，并显著改善预测初期表现。
```

第三条贡献建议避免“优于多种网格气象编码基线”作为主句，因为实验主线不是比较视觉编码器强弱，而是证明运行状态约束的增益。

### 相关工作

相关工作末段建议从“现有方法不足”改为“本文关注点不同”：

```tex
在业务预测协议下，未来气象和预测起点功率状态具有不同的信息角色：未来气象描述预测日内的外部驱动，近期实测功率反映预测起点的运行状态。已有多源融合研究通常侧重气象、功率和空间信息之间的特征互补；本文则关注真实功率状态如何作为运行状态约束参与未来气象读取。为此，本文将 query-based decoding 和可查询记忆结构用于气象读取过程，并由当前样本的场站级功率生成 dynamic power context tokens，使预测起点状态约束作用于各预测步。
```

注意这里没有说别人“不能”“难以”“不足”，而是说目标不同。

### 方法

方法里可以保留角色分工，但不使用“非对称”作为方法主名。

建议第一段改为：

```tex
如图~\ref{fig:framework} 所示，运行状态约束的气象-功率融合网络由 Weather Encoder、Power-State Encoder 和 Query Decoder 三部分组成。Weather Encoder 将连续气象预报序列编码为 weather memory tokens，作为预测日内的主驱动信息；Power-State Encoder 从预测起点前可用的场站级功率中提取当前场群状态，并生成 dynamic power context tokens；Query Decoder 使用面向各预测时刻的可学习查询向量，从融入运行状态约束的融合记忆中并行读取信息，得到日内区域集群预测序列。
```

其余方法结构可以不大改。这里的重点是证明“功率状态如何作为约束进入模型”，不是证明“非对称结构如何优于对称结构”。

### 实验

实验章节已经最贴近主线，但气象编码 baseline 的解释应进一步收窄：它们只用于交代不同气象编码器在本文设置下的结果，不承担“替代功率状态”这个机制命题。

当前：

```tex
ViT、Swin 和 Video Transformer 在该数据集上未超过 Weather-only，表明单纯提高气象视觉编码器复杂度难以解决预测起点状态失配。
```

建议：

```tex
除 Weather-only 外，3D CNN 是误差最低的气象编码基线，其性能仍低于本文方法。Weather-only 在所有纯气象基线中表现最好，说明该模型已提供较强的气象驱动参照。在相同气象输入和解码器设置下，本文方法相对 Weather-only 将整体 MAE 降低约 4.1\%、RMSE 降低约 2.9\%，说明预测起点前真实功率状态提供了有效的运行状态约束。
```

当前：

```tex
Random power 和 Zero power 保留功率侧结构但移除真实状态信息，其性能接近 Weather-only，说明单纯增加功率侧分支和参数量不足以带来同等增益。
```

这句可以保留，因为它是消融内的直接证据，不是在拉踩外部方法。

### 结论

结论当前主线基本正确。建议避免再次出现“非对称融合”之类表述，只强调：

- 未来气象仍是主导信息来源。
- 真实功率状态作为运行状态约束带来增益。
- 初始预测步收益最大。
- Random/Zero power 说明不是分支参数带来的收益。

## 推荐术语优先级

建议全文按以下优先级使用术语：

1. 主术语：`运行状态约束`
2. 支撑术语：`预测起点前真实功率状态`、`场群状态`、`状态适配`
3. 方法术语：`气象记忆`、`气象读取过程`、`动态功率上下文 token`
4. 降级术语：`非对称`，只在必要时说明信息角色分工，不作为贡献标题或方法名称

以下表达建议删除或改写：

- `更自然的建模方式是非对称气象-功率融合`
