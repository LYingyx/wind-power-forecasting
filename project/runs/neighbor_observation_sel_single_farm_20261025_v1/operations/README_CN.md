## 状态与入口

- `../STATUS.json`：中央完成/失败/活动任务；只把SUCCESS核验成功的任务计为完成。
- `REMOTE_STATUS.json`：两台V100的租约、连接、就绪和活动任务。
- `LAUNCH_LOCAL.json`、`LAUNCH_REMOTES.json`：初始调度进程号。进程可能退出，需配合状态时间和系统进程判断。
- `BOOTSTRAP.json`：本机GPU兼容检查及等待资源原因。远端相同文件在各自run目录。
- `../schedulers/*.json`：逐卡资源测量、准入原因、活动进程；本机CPU重放也在此目录。
- `../COMPLETION_AUDIT.json`：仅全部1344项成功、源码和权重核验通过后生成。

6001与4090避让外部忙碌进程；6002使用用户已明确授权的共享算力模式。每卡每轮最多加1进程，启动后至少20秒再测，保留至少4GiB或20%显存；12进程只是上限，同时受显存及92%算力利用率约束。外部负载上升时，本轮作业可在完整epoch检查点保存优化器/RNG后退出让出资源。

中央remote_controller按文件锁分配每台最多48项队列，不重复训练；网络中断时保留租约，避免把远端仍在跑的任务重发。回传核对spec及每份所选权重哈希，再删除远端重复权重。远端仅留小型结果收据。旧权重诊断保持本机运行，CPU最多4个低优先级单线程进程，CPU繁忙时等待；GPU空闲也可执行诊断。

finalize_when_done自动运行分析和完成审计，不开启2024。若出现FAILURE，不能以修改标记代替修复；应读取worker.log/FAILURE的真实异常，核查资源及数据/代码，然后在保留原因的前提下恢复受影响任务。不要重复启动已有调度器，不要重启已完成旧轮。
