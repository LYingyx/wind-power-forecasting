## 六项失败的共同原因

R4、R4-noS、R4-wrongS 的 seed 44 与 46 均在第一次验证出现 `FloatingPointError: nonfinite predictions`。已有训练损失及检查点参数有限；这不是显存不足，也不是已证明的模型发散。

[stateless_noise](code/representation.py) 的整型哈希取模后又做 XOR，可能恰好得到 `x = 2147483647`。随后 `u1 = (x + 0.5)/2147483647` 略大于 1，Box–Muller 的 `sqrt(-2 log(u1))` 产生 NaN。

两台机器分别穷举全部 1,630,585 条验证样本 × 8 条噪声样本 × 28 个分量 × 5 seeds，找到完全相同的两个异常坐标：

- seed 44：验证样本下标 245853，sample key 102483043，第 6 条样本、第 0 段、第 3 通道（均从 0 开始）。
- seed 46：验证样本下标 50954，sample key 102277694，第 7 条样本、第 6 段、第 1 通道。

只将 `u1` 的上端限制为 `(m−0.5)/m`。原本有限的所有噪声值逐元素完全相同，seed 42/43/45 没有任何改变。验证了批次切分不改变噪声、训练随机数状态不改变、六个失败检查点的原异常批次修正后全部输出有限值。训练使用 `torch.randn`，不调用这个固定验证噪声生成器。
