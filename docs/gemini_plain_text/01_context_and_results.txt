## 研究目标与约束

- 目标是单风场功率预测，预测未来 0–6 h 的 24 个 15 min 点；共享训练仍可以输出单个风场预测。
- 希望找到相对强 Transformer 有可复核优势的路线，不能只挑表现好的站点或某一个指标。
- 天气编码（含 E2L/E2C）只作实现选择与消融，不作为机制贡献点或独立贡献点。
- 共享训练、逐站独立训练、已见风场微调、完全未见风场迁移是不同设定。现有逐站微调不等于新风场迁移。
- 数据只有实测功率、Pangu 预报和 ERA5 再分析；没有场站实测天气。历史 Pangu 节点不是 ERA5。

## 当前结果的证据边界

当前协议为每日 00 UTC Pangu、15 h 后可用（北京时间 23:00 切换），气象时效 9–45 h；邻站/区域功率可用至预测起点。55 个固定风场，2022 训练、2023 选择。2024 曾在历史研究中被查看，后续只能称探索性跨年复评，不能声称完全盲测。

本轮已完成 2571 项，见[完成审计](../project/analysis/daily_protocol_review_20261115/COMPLETION_AUDIT.json)。以下为相对匹配 Transformer 的误差变化，负值为改善；口径详见[完整报告](../project/DAILY_PROTOCOL_RESULTS_REVIEW_20261115_CN.md)。

| 方案 | MAE 相对变化 | RMSE 相对变化 | 解释 |
| --- | ---: | ---: | --- |
| 共享 W0_R3 | −0.183% | +0.227% | 两项指标未同时胜出 |
| 独立 W0_R3 | −0.501% | +0.239% | MAE 优势不能覆盖 RMSE 退化 |
| 完整 W0 逐站微调 | +0.108% | +0.370% | 不支持作为当前最优路线 |
| 共享 E2L | −0.457% | −0.216% | 高功率 RMSE +0.153%，未满足原先不超过 +0.1% 的条件 |

E2L 是多层无激活线性映射，其复合仍为仿射映射。当前尚缺 Transformer 使用相同 E2L/E2C 的交叉骨干对照，不能把其收益直接归因于主干或核心机制。详见[编码角色说明](../project/ENCODING_ROLE_CLARIFICATION_20261115_CN.md)。

E2L 是七种编码中按 2023 结果挑出的，存在选择偏差；RMSE 在 seed 43、46 上落后。新任务已包含 TF_E2L，结果尚待完成。后续十种子与 2024 探索性复评用于稳定性和跨年检验，十种子本身不能消除选择偏差。

本仓库包含当前每日起报协议的实现与结果证据，供代码审阅。请沿下面的链条阅读，不要只根据结果报告推测机制。原始数据、模型权重和全量预测仍在研究服务器，因此公开仓库支持方法与记录审查，不能单独重跑完整训练或从预测重新计算全部指标。

2026-11-16 新增：[状态条件中间表示 v2 执行入口](../project/runs/daily_state_representation_20261116_v2/README_CN.md)，包含新模型、生成式教师/学生路径、预先固定的超参数、条件阶段、两机多进程调度和自动判定。阶段一 25 项已启动。下面的 2571 项完整证据仍指此前实验；不得把运行中的新路线写成已取得收益。

## 2. 模型、基线和消融怎样实现

- [共享 model.py](../project/runs/daily_protocol_restart_20261114_v1/code/model.py)：`SharedModel.__init__` 按 `family` 构建 W0、TF、TiDE、TFT、B0；`forward` 定义历史编码、天气处理、区域输入、条件适配和解码。`NeighborReadout` 定义邻站读取。
- [基线源实现](../project/runs/daily_protocol_restart_20261114_v1/code/legacy/baselines_original.py)：`TransformerFutureCov` 等；[卷积依赖](../project/runs/daily_protocol_restart_20261114_v1/code/legacy/vendor/wind_forcing/models/p0i_legacy.py)：`ResidualConv`。当前 run 的整个 `code/legacy` 已上传。
- [消融 model.py](../project/runs/daily_ablation_restart_20261114_v1/code/model.py)、[消融 data.py](../project/runs/daily_ablation_restart_20261114_v1/code/data.py)：编码变体、输入屏蔽、历史/天气对照；指定 `station` 后仅取目标风场标签进行独立训练。
- [微调 train.py](../project/runs/daily_site_finetune_20261114_v1/code/train.py) 的 `load_model`：加载共享权重，区分完整微调与头部微调，约束目标风场 embedding 更新；[site_data.py](../project/runs/daily_site_finetune_20261114_v1/code/site_data.py) 定义本站数据。

冻结依赖中包含旧实验常量与兼容代码。判断实际行为须从当前 run 的入口、`settings.py`、`manifest.json` 和调用路径出发。天气编码不是独立机制贡献；新版状态条件表示仍是[待验证计划](../project/STATE_CONDITIONED_REPRESENTATION_PLAN_20261115_CN.md)，不能当成已完成模型。

## 3. 参数、训练预算和选轮怎样确定

| 证据 | 位置 |

| 微调 1100 项 | [manifest.json](../project/runs/daily_site_finetune_20261114_v1/manifest.json)、[prepare_daily.py](../project/runs/daily_site_finetune_20261114_v1/code/prepare_daily.py) |

| 训练循环和验证选轮 | [train.py](../project/runs/daily_protocol_restart_20261114_v1/code/train.py) 的 `resolve` / `run` |

训练采用容量因子 MAE、AdamW、有效 batch 512、梯度范数裁剪 1，学习率常数；正式共享/独立任务一般最多 80 epoch、patience 10，具体以每项 manifest 为准。调参使用种子 40、41，正式比较使用 42–46。`collect.py` 按 2023 macro-MAE 的调参种子均值选配置，`resolve` 读取实际选中配置。

每项训练按验证 MAE 选一份权重，再用同一份权重报告 MAE、RMSE 等指标。微调把未修改的 epoch 0 纳入选择，同时另报预先固定的 epoch 1、6。B0 OOF 使用 2022 内部块作选择，不能误写成所有任务都用 2023 选轮。2023 同时用于选择与比较，不是独立测试集。

## 4. 每项实验的实际训练记录

## 5. 指标和汇总表怎样计算

先读 [train.py 的 evaluate](../project/runs/daily_protocol_restart_20261114_v1/code/train.py)，再读 [review_daily_results_20261115.py](../project/scripts/review_daily_results_20261115.py)。

- MAE：逐风场累计绝对误差，对该站所有样本和 24 个时效平均，再做风场等权平均。
- RMSE：每站先对样本/时效平方误差求均值并开方，再做风场等权平均。不能把它改写成所有站混在一起的一次整体 RMSE。
- **高功率样本按预测起点历史末点 `h[:, -1] >= 0.75` 划分**，不是按未来实测功率分组；高功率也不等于大爬坡。
- 分时效区间是第 1–4、5–12、13–24 点，对应 0–1 h、1–3 h、3–6 h。
- 汇总器从逐任务指标提取风场 × seed 单元，形成 [all_farm_seed_metrics.csv](../project/analysis/daily_protocol_review_20261115/all_farm_seed_metrics.csv)，再计算 [group_summary.csv](../project/analysis/daily_protocol_review_20261115/group_summary.csv) 和 [comparison_summary.csv](../project/analysis/daily_protocol_review_20261115/comparison_summary.csv)。
- 相对变化是 `100 * (候选均值 / 参照均值 - 1)`，负值改善。5 个种子与 55 站构成的 275 个单元不是 275 个独立样本；报告中的 bootstrap 区间也是描述性的。

“MAE 改善、RMSE 退化”本身不能证明削峰填谷、爬坡欠响应或天气相位漂移。归因需要读[RMSE 诊断源码](../project/runs/rmse_gap_diagnostic_20261115/)和[爬坡诊断源码](../project/runs/ramp_information_diagnostic_20261115/)，并核对实际诊断输出。两个诊断 README 主要记录脚本用途，不包含全部诊断数值；未持久化的对话/控制台输出不能冒充仓库中的实证。

## 1. 手稿中的时间规则（原文要点）

- **起报**：每天一次，北京时间 D−1 日 08:00 起报（00 UTC）。
- **首次使用时刻**：该起报在 D−1 日 23:00 首次用于功率预测（t0），即起报后 15 h，并服务于 D 日全天。
- **历史段与目标段**：同一次起报中，从时效 0 到 t0 的帧作为"气象预报历史段"，t0 之后的帧作为目标段；两段拼接输入，不跨期次。

## 比较口径

- 任务0–6 h、24个15 min预测点；Pangu每天00 UTC，15 h后可用；邻站/区域功率可用至起点。2022训练，2023选超参数与检查点；固定55站，每站验证起点29647个。
- **W0**是本框架的无轨迹条件模型，默认天气编码E2C；**TF**是已调参Transformer。**BASE**使用本站历史、天气和站点信息；**R3**增加SEL物理/状态特征、近邻汇总与三环区域功率。单风场预测输出、参数共享训练、是否使用邻站输入是三个不同维度。
- E2L使用原始14天气通道与三层线性映射，保留W0其余结构及R3输入；E2N是同输入、同参数数量但含GELU的控制。E2L不是新风场迁移模型，也不是已经验证的独立单站模型。
- 指标是容量因子误差，不是MW。表中数值为55站×5seeds等权汇总，百分比为`100×(候选/参照−1)`；负数更好。改善站数比较每站完整5seed均值，不能替代逐seed原值。高功率按起点当前容量因子≥0.75定义，不是按未来目标筛选。
- [逐风场逐seed原始指标](analysis/daily_protocol_review_20261115/all_farm_seed_metrics.csv)、[关键逐seed与全55站明细](analysis/daily_protocol_review_20261115/FARM_AND_SEED_DETAILS_CN.md)、[所有配对原值](analysis/daily_protocol_review_20261115/paired_farm_seed_comparisons.csv)保留全部改善和退化。
- 2023同时用于选择和报告，尤其微调允许第0轮参与选模，相对底座的MAE收益存在选择优势。不能把这些差异直接当作独立泛化证据。描述性风场bootstrap没有处理空间依赖、多重比较或选模，不能据其宣称独立统计显著。2024尚未在本轮复评，且历史已看过，只能称探索性跨年复评。

## 建议路线与贡献边界

**当前决策：原版E2C-CBH、新风场迁移、以及“独立训练全面压过TF”都不宜作为已确立的主路线。** 如果只考虑本轮已见风场的预测误差，TF全参数微调是核心部署方案中的优先参照；如果必须保持本模型，优先候选为“共享参数、逐风场输出、R3输入、E2L天气映射、无CB/CBH条件”。

建议把后续工作限定为有判别力的验证，避免先铺大矩阵：

1. 冻结E2L候选与同输入TF、E2C、E2N对照，先在预先固定的时间段/新增随机种子检查RMSE与高功率表现。现有E2L是在2023消融结果中挑出的优胜项，必须明确选择偏差。正式部署比较同时保留TF个性化参照。
2. 如果硬约束是完全独立训练，则补E2L逐站独立对照；当前1100项独立矩阵只有默认E2C的W0与TF，不能把共享E2L成绩直接挪用。若需新风场迁移，必须另做训练风场完全留出的设计，本站数据预算及适应步骤对W0/TF一致。
3. 保持0–6 h主任务和MAE/RMSE/高功率指标，冻结后再做2024探索性跨年复评。不能事后只保留有利时效、风场或将主指标改成RMSE来包装Z1。

以下仅作为研究工作的组织结构，不能预设为三个独立贡献；编码不列为机制或独立创新：

|方向|当前已有证据|尚不能宣称|
|---|---|---|
|整体单风场预测框架（方法贡献待验证）|完整框架已有性能与消融结果；编码只是实现选择|编码本身为创新；核心结构已在相同编码下胜过TF；独立/迁移已赢|
|消融归因（支撑证据）|输入删除、编码替换、错日期条件、历史×天气矩阵已重训|将编码替换单列为机制贡献；信息收益只属于W0；预测交互等于因果机制|
|业务适用边界：真实可用时刻、共享/独立/个性化、55站与分时效分析|统一每日00 UTC/15 h协议，全55站5seed原值，明确0–1 h与3–6 h差异|业务协议本身等于算法创新；只展示赢的风场可证明总体优势|

以上是方法、支撑分析、适用边界三部分；不把编码列为贡献，也不强凑三个已经成立的机制点。若后续E2L仍不能在约定条件下胜过同输入Transformer，应明确否决该优势叙事。

# 编码角色与公平对照说明

用户最新约束：**不把天气编码作为机制贡献点或独立贡献点。** 此约束取代此前结果报告中围绕“简化天气映射”组织贡献的建议。编码结果及性能原值不变；本次不启动额外训练。

## E2L具体是什么

E2L是项目内部实验编号，L表示linear。当前选定width64，天气支路为：

`标准化14通道天气 → Linear(14,64) → Linear(64,64) → Linear(64,64)`

中间没有GELU等非线性激活，三层带偏置线性层合起来仍是一个仿射映射`z = Wx + b`。多层参数化会影响优化、权重衰减和训练轨迹，但不扩大这一支路的仿射函数集合。整个预测模型仍有非线性历史编码器、解码器等部分，不能称为线性预测模型。实现见 [当前模型定义](runs/daily_ablation_restart_20261114_v1/code/model.py:54) 和 [天气输入选择](runs/daily_ablation_restart_20261114_v1/code/model.py:119)。

因此，E2L不是原来的复杂柱坐标编码，也不是新提出的机制；它最初是控制“多层参数化”和“非线性激活”影响的对照版本。

## 已经做过哪些编码对照

|编号|天气支路输入|映射|主要回答的问题|
|---|---|---|---|
|E0|原始14通道|单层线性|基本天气投影|
|E1|原始14通道＋地形高度|单层线性|天气支路直接提供地形高度的影响|
|E2L|原始14通道|三层线性，无激活|多层线性参数化|
|E2N|原始14通道|三层MLP，含GELU|对E2L，严格同参数量检验非线性|
|E2|原始14通道＋地形高度|三层MLP，含GELU|对E1检验非线性参数化；对E2N检验天气支路高度输入|
|E2C|15维柱坐标表示|与E2相同形状的MLP|同参数量比较原始坐标与柱坐标|
|E3|柱坐标分三组|分组MLP再融合|分组编码；不严格等参数量|

E2C将近地、低层、层间差分等组成15维表示，可由原始14天气变量和地形高度恢复；它没有新增观测天气信息。所有当前模型的站点静态支路本身已有地形高度，所以E1/E2并不是首次向整个模型引入地形信息。E2C改动也包含相应训练期归一化，现有比较不把坐标变换和归一化分离。

上述7种版本都在无轨迹条件与CBH两种背景下，以5个seed、同一55站共享训练评估；E2C复用本轮已经重训的W0_R3/M2_CBH。它们是**同一框架内部的编码对照**，不是7个独立外部baseline。各编码沿用对应W0的已选超参数，没有逐编码另做等预算搜索，所以结论限定于当前训练设置。

结果没有支持“复杂编码一定更好”：无条件下E2L比E2C的MAE/RMSE低0.275%/0.442%；原始天气＋高度的E2也比E2C低0.121%/0.141%。CBH背景部分排序变化，不能把无条件下E2L胜出直接推广到所有背景。

## 现有对照还缺什么

当前TF_R3使用原始天气的线性投影加时效特征；它获得相同原始信息、SEL与区域观测，但没有挂接完全相同的E2C/E2L天气模块。TiDE/TFT也没有做这一模块互换。

“本模型内部替换编码”可以检验该组件在本模型中的作用；“本模型与标准TF”可以比较端到端预测性能。两者都不能单独回答“优势来自本模型核心结构，还是来自天气前端”。

如果保留复杂E2C，应补充最小的骨干×编码交叉对照：

|骨干|共同简单天气前端|共同E2C复杂天气前端|
|---|---|---|
|本模型|重新明确共同接入方式|本模型＋E2C|
|Transformer|相同前端，保留各自必要时效接口|Transformer＋同一个E2C|

如果最终选用E2L，同样补TF＋E2L。两边使用同一预报、历史功率、SEL/区域观测、站点信息、划分与种子，并控制新增模块及调参预算；时间特征应走明确分开的公共接口，避免把删掉TF时效特征误当作编码替换。保持编码相同的行间比较回答骨干差异，同一骨干内的列间比较回答编码增益。比较数值而不是强求模块必须提升。

该矩阵是待补的公平性对照，不是已完成实验。无需仅为了对照数量增加更多编码名称。

## 如何定位贡献

编码保留为模型实现选择及消融项，是否采用由性能、稳定性和计算成本决定；正文无需把它列为独立创新。

研究主张应围绕完整单风场预测框架，以及在相同信息和合理训练预算下对强baseline的稳定优势。若要声称某个核心机制有效，需在固定编码后单独移除、替换或错配该机制；当前CB/CBH和RM结果还不支持将其直接写为已经成立的机制贡献，历史×天气交互也不是W0独占的现象。

不能因为编码不作为贡献，就自动把CBH、物理特征或交互分析改名为三个新机制。后续路线先解决完整模型的公平性能优势和真正机制的可识别增益；在此之前，不预设三个已成立的正向贡献。

原始完整结果、逐风场逐seed原值及限制仍见 [完整重训报告](DAILY_PROTOCOL_RESULTS_REVIEW_20261115_CN.md)。

# 状态条件 15 min 中间表示：最终执行方案（v2）

日期：2026-11-16（取代 11-15 初版）。

执行入口：[daily_state_representation_20261116_v2/README_CN.md](runs/daily_state_representation_20261116_v2/README_CN.md)。实现、预写定任务、自动门槛、两机多进程调度与运行状态均在该目录。已启动阶段一不等于已有新结果；后续阶段依门槛启用。

协议：每日 00 UTC 起报、起报后 15 h 可用；0–6 h、15 min 分辨率；55 站共享训练；2022 训练、2023 选择。

宿主模型：`ENC_neutral_E2L`（下文 R0）。R0 是从 7 种编码中按 2023 年结果挑出的，存在选择偏差，最终结论必须靠 10 seeds 和 2024 复评确认。

## 0. 依据（零训练诊断）

- **误差在小时尺度上**：目标落在整点和 :15 / :30 / :45 的 MSE 相差不超过 ±0.6%，与这些时刻本身的难度一致。线性插值没有造成小时内部的损失，所以 Δ 必须在小时尺度上组织变化，而不是逐点补细节（`runs/rmse_gap_diagnostic_20261115/phase.py`）。
- **W0 的 RMSE 劣势来自真实的大变化**：实际变化超过 0.3 时，W0 少跟了一些（3–6 h 跟上 54.6%，TF 为 55.6%）。做 5-seed 集成后差距仍在，属于结构性问题。
- **运行状态决定天气变化能否兑现**：按当前功率与变化方向分组，天气信号的误报率从 27% 到 100% 不等；把天气信号按可变化空间截断后，误报率从 56% 降到 46%（`runs/ramp_information_diagnostic_20261115/state.py`）。
- **W0 的查询中没有当前功率水平**：SEL-STATE 只有波动和差分，不含功率水平；当前功率只能经由历史记忆间接得到，TF 的输出头则直接读取当前功率。但旧协议下单站训练、10 seeds 的输出头 2×2 实验已经测过"给 W0 输出头加当前功率"：MAE +0.021%、RMSE −0.005%，没有作用。因此这里只把它当作 R3 状态 c 的一个分量，外加一个低成本对照，不当作修复手段。

## 1. 模块（只替换"天气 → 解码器查询"这一段）

- **小时潜表示**：8 个小时节点（同一次起报）经 E2L 编码，得到 z_0 … z_7；另加一阶差分 δz_m = z_{m+1} − z_m 作为输入（线性变换，不单列为机制）。
- **状态 c**（只用起点前可得的信息）：
  - 当前功率 h、可变化空间 1 − h；
  - 近 1 h 与近 6 h 的功率变化率；
  - SEL-STATE；
  - 三环区域的当前值与 1 h 变化。
- **窗口级生成器**：一个小型 Transformer 读取完整的 [z_0..7, δz, c]，为每个小时段输出 p 维参数（p = 4，表示时机与幅度）。再用固定的平滑核展开到 24 个 15 min 点，得到 Δ_k。
  - 生成器可以在小时之间重新分配变化（例如把 1 h 后的变化信号提前），这正是"误差在小时尺度"所要求的；
  - 输出层零初始化。
- **15 min 潜表示**：u_k = lerp(z)(t_k) + W·Δ_k，替代原来的天气查询分量。

## 2. 阶段一：确定性筛选（5 seeds，训练设置与 R0 完全一致）

| 编号 | 内容 | 作用 |
|---|---|---|
| R0 | 现有 `ENC_neutral_E2L`（已有结果） | 参照 |
| R0+H | R0 的输出头额外读取 [h, 1 − h]，其余不变 | 排除"收益只来自把当前功率接到输出头" |
| R1 | 先编码，再在潜空间线性插值（Δ = 0） | 插值放在哪一侧的影响 |
| R2 | 窗口级 Δ，不含 c | 表示空间细化本身 |
| R3 | 窗口级 Δ，含 c | **主候选（确定性）** |
| TF_E2L | TF_R3 的天气投影换成同样的 E2L | 同编码跨骨干对照（复盘文档列出的缺项） |

## 3. 阶段二：生成式（R3 至少相对 R2 双指标改善时才做）

| 编号 | 内容 |
|---|---|
| R4 | 在 §1 的每小时段 p 维参数空间里，用条件流匹配建模 p(参数 \| z, δz, c) |
| R4-noS | R4 去掉 c |
| R4-wrongS | R4 的 c 换成同月同钟点另一日的状态（训练与评价都换） |

实现要点：
- **教师**（只在训练时使用）：输入实际变化 Δy = y − h，以及插值潜表示相对起点的变化 lerp(z)(t_k) − lerp(z)(0)，输出每小时段的 p 维参数；加噪声与 KL 约束，防止直接抄目标。
- **学生路径**：训练时并行采样 4 条轨迹，用 4 条的平均功率预测计算 MAE。这样减轻逐条点预测损失对随机性的惩罚，但不能保证分布不坍缩，须另报样本离散度。
- **损失**：教师路径 MAE + 学生路径 MAE + 0.1 × 流匹配损失。
- **推理**：采样 8 次，功率预测取均值（预先写定；样本中位数另行报告，不参与选择）。
- **冒烟测试**：参数为 0 时输出等于 R1；教师不出现在推理路径；采样过程可以反传；8 个样本之间的离散度不为 0。

规模：3 组 × 5 = 15 次共享训练。R4 通过后，再做 TF + R4（5 次），检验是否依赖骨干。

## 4. 阶段三：损失复核（一次，两个骨干同时做）

- 在最终候选与 TF_R3 上各跑 MAE + 0.2·MSE（5 seeds，共 10 次）。
- 只有当"两个骨干都用这个损失时，本模型对 TF 的 MAE 与 RMSE 都胜出，且本模型自身两个指标都不劣于纯 MAE"时才采用；否则保持纯 MAE。
- **不采用**：一阶差分损失（在时机不确定时会逼出更陡、时间错位的预测，抬高 RMSE）、按实际变化幅度加权、改用 RMSE 或综合分选检查点、只对候选模型改训练流程。

## 5. 判定（预先写定）

- **主判定**：候选模型相对 R0 和同信息 TF 中较强的一个（TF_R3 或 TF_E2L），同时满足：
  - MAE 与 RMSE 都改善 ≥ 0.1%；
  - 两个指标各自过半风场改善；
  - 5 个 seed 中至少 4 个 seed 两个指标都改善；
  - 高功率 RMSE 退化 ≤ 0.1%。
- **机制判定**：
  - R3 必须同时胜过 R2 和 R0+H，才说明"状态条件"是收益来源，而不只是把当前功率接给输出头；
  - R4 必须同时胜过 R3、R4-noS、R4-wrongS，才说明"生成式"和"状态条件"都起作用；
  - 达不到就保留通过的那一级（R3 或线性插值），如实报告。
- **必报诊断**（不作为门槛）：
  - 分时效段结果；
  - 整点 / 非整点误差表（收益若只出现在非整点，视为无效）；
  - 实际变化 > 0.3 样本上的 ΔMSE 与"跟上比例"；
  - 高功率组上行、下行分开统计。
